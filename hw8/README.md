# Домашня робота з лекції № 8
## Тема: Асемблер

### Завдання 1. Підпрограма `cube(x)`

За домовленістю виклику RISC-V аргумент передається в `a0`, а результат повертається в `a0`. Тимчасово зберігаю початкове `x` у caller-saved регістрі `t0`, обчислюю квадрат і множу його на `x`.

```asm
cube:
    mv   t0, a0          # зберегти x
    mul  a0, a0, a0       # a0 = x * x
    mul  a0, a0, t0       # a0 = x * x * x
    ret                   # повернути результат у a0
```

Підпрограма використовує дві інструкції `mul`. Наприклад, якщо на вході `a0 = 3`, то після першого множення `a0 = 9`, а після другого — `a0 = 27`.

### Завдання 2. Виклик `square` з `main`

Розглянемо послідовність:

```asm
li   a0, 6
jal  ra, square
# виконання продовжується тут після ret
```

Нехай адреса інструкції `jal` — `P`, а адреса наступної інструкції — `R = P + 4`. Для звичайного 32-бітного коду `jal` записує адресу повернення `R` у `ra` і передає керування на `square`. Початкове значення `ra` залежить від коду, який викликав `main`, тому позначимо його `ra₀`.

| Крок | Виконання | `a0` | `ra` |
|---|---|---:|---|
| До `li` | Початковий стан | початкове значення | `ra₀` |
| Після `li a0, 6` | Завантаження аргументу | `6` | `ra₀` (без змін) |
| До переходу в `square` | `jal ra, square` записує адресу повернення | `6` | `R = P + 4` |
| У `square` | `mul a0, a0, a0` | `36` | `R` |
| Після `ret` | Повернення за адресою `R` | `36` | `R` |

У підпрограмі `square` для цього прикладу достатньо такої послідовності:

```asm
square:
    mul  a0, a0, a0       # 6 * 6 = 36
    ret                   # повернення за адресою, збереженою в ra
```

`ret` є псевдоінструкцією повернення, яка переходить за адресою в `ra` (еквівалент `jalr x0, 0(ra)`). Вона не змінює `a0` і не перезаписує `ra`; керування повертається до інструкції, що йде після виклику.

### Завдання 3. Доступ до елементів масиву в RISC-V і x86

У матеріалах папки немає прикладів суми масиву з розділу 7, тому нижче наведено типові репрезентативні рядки для порівняння способів доступу до пам'яті.

**RISC-V — окремо завантажити елемент, потім додати його до суми:**

```asm
lw   t0, 0(a0)           # завантажити елемент масиву з пам'яті в t0
add  t1, t1, t0          # додати значення з t0 до суми
```

**x86-64 (синтаксис AT&T) — додати значення з пам'яті безпосередньо до суми:**

```asm
addl (%rdi), %eax        # прочитати елемент за адресою в rdi і додати до eax
```

У RISC-V арифметична команда `add` працює з регістрами, тому значення спочатку читається з пам'яті окремою командою `lw`. У наведеній команді x86 арифметична операція може мати операнд у пам'яті: `addl` читає значення за адресою в `%rdi` і одразу додає його до `%eax`. Отже, відрізняється спосіб запису доступу до пам'яті: явна пара load + arithmetic у RISC-V проти одного рядка з операндом пам'яті в x86.
