# Домашня робота з лекції №6

### 1. Ієрархія пам'яті

У наявних матеріалах репозиторію таблиці з розділу 1 немає, тому нижче наведено типові орієнтовні значення для сучасного комп'ютера. Фактичні обсяги та затримки залежать від процесора, конфігурації пам'яті й накопичувача. Обсяги кешів наведено на ядро для L1/L2 та спільного кешу для L3.

```text
                 ┌─────────────────────────────┐
                 │ Регістри CPU                │
                 │ ≈ 1 КБ; < 1 нс              │
                 └─────────────────────────────┘
              ┌───────────────────────────────────┐
              │ L1: 32–64 КБ на ядро; ≈ 1 нс      │
              └───────────────────────────────────┘
           ┌─────────────────────────────────────────┐
           │ L2: 256 КБ–2 МБ на ядро; ≈ 3–5 нс       │
           └─────────────────────────────────────────┘
        ┌───────────────────────────────────────────────┐
        │ L3: 4–64 МБ спільного кешу; ≈ 10–20 нс        │
        └───────────────────────────────────────────────┘
     ┌─────────────────────────────────────────────────────┐
     │ DRAM: кілька–десятки ГБ; ≈ 50–100 нс                │
     └─────────────────────────────────────────────────────┘
  ┌───────────────────────────────────────────────────────────┐
  │ Диск: сотні ГБ–кілька ТБ; SSD ≈ 50–200 мкс, HDD ≈ 5–10 мс │
  └───────────────────────────────────────────────────────────┘

       ↑ швидше, менший обсяг, вища вартість на байт
       ↓ повільніше, більший обсяг, нижча вартість на байт
```

Із рухом униз ієрархією зазвичай збільшується місткість, але зростає час доступу. Регістри та кеші розташовані близько до процесора й дають швидкий доступ до часто потрібних даних; DRAM і диск мають більшу місткість, але повільніші.

### 2. Обхід двовимірного масиву

У C елементи двовимірного масиву зберігаються в пам'яті послідовно за рядками (row-major order). Для `int a[100][100]` елементи одного рядка розташовані поруч, а перехід до наступного рядка відбувається після всіх 100 елементів поточного рядка.

**Обхід по рядках — внутрішній цикл проходить стовпці:**

```c
for (int i = 0; i < 100; ++i) {
    for (int j = 0; j < 100; ++j) {
        use(a[i][j]);
    }
}
```

**Обхід по стовпцях — внутрішній цикл проходить рядки:**

```c
for (int j = 0; j < 100; ++j) {
    for (int i = 0; i < 100; ++i) {
        use(a[i][j]);
    }
}
```

Менше промахів кешу зазвичай дає обхід **по рядках**. Послідовні звернення `a[i][0]`, `a[i][1]`, … читають сусідні значення, які найчастіше потрапляють в один кеш-рядок. Це використовує **просторову локальність**. За обходу по стовпцях сусідні звернення віддалені в пам'яті на розмір одного рядка — `100 × sizeof(int)`, зазвичай 400 байтів. Через це завантажений кеш-рядок використовується менш ефективно, а промахів кешу може бути більше. Обидва варіанти обходять ті самі елементи; різниця — у порядку звернень до пам'яті.

### 3. Витіснення брудного рядка кешу

За стратегії **write-back** запис у кеш змінює копію даних у кеш-рядку, а відповідна копія в наступному рівні пам'яті може тимчасово залишатися старою. Ознака `dirty` показує, що кеш-рядок змінено й дані ще не записані далі. Коли такий рядок витісняють, кеш перед звільненням місця записує його актуальний вміст на наступний рівень ієрархії (зазвичай у кеш нижчого рівня або DRAM). Це запобігає втраті змін, але витіснення брудного рядка потребує додаткового запису.

За стратегії **write-through** кожен запис у кеш одночасно передається і на наступний рівень пам'яті. Тому під час звичайного витіснення рядка немає потреби додатково записувати його змінений вміст: пам'ять уже містить актуальні дані. Такий підхід спрощує узгодження копій, але створює більше операцій запису до нижчого рівня; їхню затримку можуть приховувати буфери запису.

| Стратегія | Коли дані записуються на наступний рівень? | Дія при витісненні |
|---|---|---|
| Write-back | Переважно при витісненні зміненого рядка | Брудний рядок спочатку записується далі, після чого його можна замінити |
| Write-through | Під час кожного запису в кеш | Додатковий запис рядка при витісненні не потрібен |

## Висновок

Ієрархія пам'яті поєднує швидкі маломісткі рівні з повільнішими рівнями більшої місткості. Послідовний обхід масиву в порядку його зберігання в C використовує просторову локальність і зазвичай зменшує кількість промахів кешу. Для write-back брудний рядок потрібно записати на нижчий рівень при витісненні, тоді як write-through передає зміни далі вже під час кожного запису.
