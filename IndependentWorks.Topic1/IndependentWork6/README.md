# Звіт з самостійної роботи №6

**Варіант:** №10

## Завдання 1. Розрахунок бітів зміщення ($offset\_bits$) та бітів номера сторінки ($vpn\_bits$)

1. **Біти зміщення ($offset\_bits$):**  
   Розмір сторінки дорівнює $16\text{ КБ} = 16 \times 1024\text{ Б} = 16\,384\text{ Б} = 2^{14}\text{ Б}$.  
   Для адресації кожного байта всередині сторінки потрібна кількість бітів, що дорівнює показнику степеня двійки:
   $$\text{offset\_bits} = \log_2(\text{розмір\_сторінки}) = \log_2(16\,384) = 14\text{ біт}$$

2. **Біти номера віртуальної сторінки ($vpn\_bits$):**  
   Номер сторінки займає решту старших розрядів віртуальної адреси:
   $$\text{vpn\_bits} = \text{розрядність\_адреси} - \text{offset\_bits} = 32 - 14 = 18\text{ біт}$$

> **Результат:** $\text{offset\_bits} = 14\text{ біт}$, $\text{vpn\_bits} = 18\text{ біт}$.

## Завдання 2. Обчислення розміру повної однорівневої таблиці сторінок

1. **Кількість записів у таблиці сторінок:**
   $$N_{\text{PTE}} = 2^{\text{vpn\_bits}} = 2^{18} = 262\,144\text{ записів}$$

2. **Загальний обсяг таблиці сторінок:**
   $$\text{Розмір Таблиці} = N_{\text{PTE}} \times \text{Розмір PTE} = 262\,144 \times 4\text{ Б} = 1\,048\,576\text{ Б}$$

Переведемо отримане значення у зручні одиниці виміру:
$$1\,048\,576\text{ Б} = \frac{1\,048\,576}{1024}\text{ КБ} = 1024\text{ КБ} = 1\text{ МБ}$$

> **Результат:** Обсяг однорівневої таблиці сторінок становить **$1\text{ МБ}$**.

## Завдання 3. Розбиття віртуальної адреси `0x02ABCDEF` на VPN та offset

Вхідна 32-бітна адреса: `0x02ABCDEF` (у десятковій формі: $44\,809\,711_{10}$).

1. **Обчислення зміщення (offset):**
   $$\text{offset} = \text{Віртуальна\_адреса} \pmod{\text{Розмір\_сторінки}} = 44\,809\,711 \pmod{16\,384} = 3567_{10}$$
   Переведення у шістнадцятковий вигляд:
   $$3567_{10} = \text{0x0DEF}$$

2. **Обчислення номера віртуальної сторінки (VPN):**
   $$\text{VPN} = \left\lfloor \frac{\text{Віртуальна\_адреса}}{\text{Розмір\_сторінки}} \right\rfloor = \left\lfloor \frac{44\,809\,711}{16\,384} \right\rfloor = 2734_{10}$$
   Переведення у шістнадцятковий вигляд:
   $$2734_{10} = \text{0xAA6}$$

*Перевірка через бітові операції:*  
Двійкове представлення `0x02ABCDEF`:
$$\underbrace{0000\,0010\,1010\,1011\,11}_{\text{VPN (18 біт)}} \, \underbrace{00\,1101\,1110\,1111}_{\text{Offset (14 біт)}}$$
* Старші 18 біт: `000000101010101111`$_2$ = `0xAA6` ($2734_{10}$)
* Молодші 14 біт: `00110111101111`$_2$ = `0x0DEF` ($3567_{10}$)

> **Результат:**
> * **VPN:** $2734_{10}$ = **`0xAA6`**
> * **Offset:** $3567_{10}$ = **`0x0DEF`**

## Завдання 4. Трансляція у фізичну адресу

1. **Обчислення номера фізичного фрейму (PFN):**
   $$\text{номер\_фрейму} = \text{VPN} + 0\text{x}100 = 0\text{xAA6} + 0\text{x}100 = 0\text{xBA6} \quad (2734 + 256 = 2990_{10})$$

2. **Обчислення підсумкової фізичної адреси:**
   $$\text{Фізична\_адреса} = \text{номер\_фрейму} \times \text{розмір\_сторінки} + \text{offset}$$
   $$\text{Фізична\_адреса} = 2990 \times 16\,384 + 3567 = 48\,988\,160 + 3567 = 48\,991\,727_{10}$$

   Переведемо у шістнадцятковий вигляд:
   $$\text{Фізична\_адреса (hex)} = (0\text{xBA6} \ll 14) \mid 0\text{x0DEF} = 0\text{x02E98000} \mid 0\text{x0DEF} = \text{0x02E98DEF}$$

> **Результат:** Фізична адреса = **`0x02E98DEF`**.

## Завдання 5. Моделювання роботи TLB (Розмір = 8, LRU)

Ємність TLB становить 8 записів. Дисципліна заміщення — **LRU** (Least Recently Used: найменш недавно використаний елемент знаходиться на початку списку, щойно використаний — додається/пересувається в кінець).

#### Покрокове трасування звернень:

| Крок | Запитувана сторінка | Стан TLB до звернення | Результат (Hit/Miss) | Стан TLB після звернення | Опис дії |
| :-: | :-: | :--- | :-: | :--- | :--- |
| **1** | **0** | `[]` (порожній) | **Miss (М)** | `[0]` | Запис 0 відсутній (холодний промах). Додано в TLB. |
| **2** | **1** | `[0]` | **Miss (М)** | `[0, 1]` | Запис 1 відсутній. Додано в TLB. |
| **3** | **2** | `[0, 1]` | **Miss (М)** | `[0, 1, 2]` | Запис 2 відсутній. Додано в TLB. |
| **4** | **0** | `[0, 1, 2]` | **Hit (Н)** | `[1, 2, 0]` | **Влучання!** Запис 0 оновлено як найновіший (переміщено в кінець). |
| **5** | **3** | `[1, 2, 0]` | **Miss (М)** | `[1, 2, 0, 3]` | Запис 3 відсутній. Додано в TLB. |
| **6** | **1** | `[1, 2, 0, 3]` | **Hit (Н)** | `[2, 0, 3, 1]` | **Влучання!** Запис 1 оновлено як найновіший (переміщено в кінець). |

*Примітка:* Оскільки розмір TLB ($8$) перевищує максимальну кількість унікальних сторінок у послідовності ($4$), витіснення (eviction) за заповненістю не відбувалося.

#### Підсумкові результати моделювання:
* **Послідовність результатів (Н/М):** **Miss, Miss, Miss, Hit, Miss, Hit** (`M, M, M, H, M, H`)
* **Загальна кількість звернень:** $6$
* **Кількість влучань (Hits):** $2$
* **Кількість промахів (Misses):** $4$

## Відповіді на контрольні запитання

### 1. Чому кількість бітів зміщення в сторінці завжди дорівнює показнику степеня двійки в розмірі сторінки?
У комп'ютерних системах пам'ять адресується побайтово. Щоб адресувати будь-який із $N = 2^k$ байтів усередині сторінки розміром $N$, потрібна комбінація з $k$ бітів ($k = \log_2 N$). Використання степеня двійки дає змогу апаратно відокремити номер сторінки від зміщення без додаткових обчислень — шляхом простого розділення двійкового розрядного сітки адреси на дві частини.

### 2. У чому принципова відмінність між TLB-промахом і сторінковим промахом (page fault)?
* **TLB-промах (TLB miss):** Виникає, коли запис про трансляцію потрібної сторінки відсутній у швидкісному кеші TLB, але сама сторінка перебуває в оперативній пам'яті (RAM). Обробляється швидко апаратним або програмним шляхом (зчитування з Таблиці Сторінок).
* **Сторінковий промах (Page fault):** Виникає, коли сама сторінка відсутня у фізичній оперативній пам'яті (скинута на диск у файл підкачки / swap). Це апаратне переривання, яке вимагає звернення до повільного диска операційною системою та завантаження сторінки в RAM.

### 3. Чому перше звернення до будь-якої сторінки в послідовності завжди дає TLB-промах?
Перше звернення до будь-якої сторінки призводить до так званого "холодного промаху" (cold miss або compulsory miss), тому що на момент старту роботи програми або перед первинним доступом інформація про трансляцію цієї сторінки ще ніколи не завантажувалася в буфер TLB.
