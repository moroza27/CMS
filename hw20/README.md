# Звіт з домашнього завдання до лекції №20

## Завдання 1: Проєктування логічної схеми мережі малого офісу

### 1.1. Вимоги до мережі та кількісний склад

Мережа малого офісу повинна обслуговувати три структурні підрозділи, публічний вебсервер (DMZ), службу внутрішнього управління та забезпечувати безперебійний вихід в інтернет через двох незалежних провайдерів (ISP1 — основний, ISP2 — резервний).

**Потреба в хостах по сегментах:**
1. **Відділ IT та Розробки (VLAN 10):** 50 робочих станцій.
2. **Відділ Продажів (VLAN 20):** 28 робочих станцій.
3. **Бухгалтерія та Кадри (VLAN 30):** 12 робочих станцій.
4. **Публічна зона / DMZ (VLAN 40):** Вебсервер (фронтенд) та публічні сервіси — 5 хостів.
5. **Службовий сегмент Управління / Management (VLAN 99):** Інтерфейси керування комутаторами, маршрутизаторами та точками доступу — 6 пристроїв.

### 1.2. Розрахунок IP-адресації методом VLSM

Для побудови адресного плану виділено базовий блок приватних IP-адрес: $192.168.100.0/24$ (загальна кількість IPs: $2^{32-24} = 256$).

Кількість корисних хостів для підмережі з маскою $/Prefix$ обчислюється за формулою:
$$N_{\text{usable}} = 2^{32 - \text{Prefix}} - 2$$

Сортуємо підмережі за спаданням потреби в хостах:

1. **VLAN 10: Відділ IT та Розробки (потреба: 50 хостів)**
   * Шукаємо найменший розмір блоку: $2^n - 2 \ge 50 \implies n = 6$ біт для хостів ($2^6 - 2 = 62 \ge 50$).
   * Префікс маски: $32 - 6 = 26$ ($\text{маска } 255.255.255.192$).
   * **Адреса мережі:** $192.168.100.0/26$
   * **Діапазон адресації хостів:** $192.168.100.1 - 192.168.100.62$
   * **Шлюз за замовчуванням (Gateway):** $192.168.100.1$
   * **Широкомовна адреса (Broadcast):** $192.168.100.63$

2. **VLAN 20: Відділ Продажів (потреба: 28 хостів)**
   * Шукаємо найменший розмір блоку: $2^n - 2 \ge 28 \implies n = 5$ біт для хостів ($2^5 - 2 = 30 \ge 28$).
   * Префікс маски: $32 - 5 = 27$ ($\text{маска } 255.255.255.224$).
   * **Адреса мережі:** $192.168.100.64/27$
   * **Діапазон адресації хостів:** $192.168.100.65 - 192.168.100.94$
   * **Шлюз (Gateway):** $192.168.100.65$
   * **Broadcast:** $192.168.100.95$

3. **VLAN 30: Бухгалтерія та Кадри (потреба: 12 хостів)**
   * Шукаємо найменший розмір блоку: $2^n - 2 \ge 12 \implies n = 4$ біти ($2^4 - 2 = 14 \ge 12$).
   * Префікс маски: $32 - 4 = 28$ ($\text{маска } 255.255.255.240$).
   * **Адреса мережі:** $192.168.100.96/28$
   * **Діапазон адресації хостів:** $192.168.100.97 - 192.168.100.110$
   * **Шлюз (Gateway):** $192.168.100.97$
   * **Broadcast:** $192.168.100.111$

4. **VLAN 40: Публічна зона / DMZ (потреба: 5 хостів)**
   * Обчислення: $2^n - 2 \ge 5 \implies n = 3$ біти ($2^3 - 2 = 6 \ge 5$).
   * Префікс маски: $32 - 3 = 29$ ($\text{маска } 255.255.255.248$).
   * **Адреса мережі:** $192.168.100.112/29$
   * **Діапазон адресації хостів:** $192.168.100.113 - 192.168.100.118$
   * **Шлюз (Gateway):** $192.168.100.113$
   * **Broadcast:** $192.168.100.119$

5. **VLAN 99: Management (потреба: 6 пристроїв)**
   * Обчислення: $2^n - 2 \ge 6 \implies n = 3$ біти ($2^3 - 2 = 6 \ge 6$).
   * Префікс маски: $32 - 3 = 29$ ($\text{маска } 255.255.255.248$).
   * **Адреса мережі:** $192.168.100.120/29$
   * **Діапазон адресації хостів:** $192.168.100.121 - 192.168.100.126$
   * **Broadcast:** $192.168.100.127$

*Невикористаний резерв адресації:* $192.168.100.128/25$ (128 вільних IP-адрес для подальшого розширення мережі).

### 2.3. Розподіл обладнання за ієрархічною моделлю

1. **Рівень Ядра (Core Layer):**
   * **Обладнання:** Маршрутизатор / Міжмережевий екран високої продуктивності (наприклад, Edge Router / Firewall).
   * **Функції:** Високошвидкісна пересилка трафіку, термінація BGP/Policy-Routing для двох провайдерів (ISP1 та ISP2), реалізація NAT/PAT, підключення до DMZ.

2. **Рівень Розподілу (Distribution Layer):**
   * **Обладнання:** L3-комутатор (Layer 3 Switch).
   * **Функції:** Маршрутизація між VLAN (Inter-VLAN routing), застосування списків доступу (ACL) для ізоляції Бухгалтерії від Відділу Продажів, агрегація трафіку з комутаторів доступу.

3. **Рівень Доступу (Access Layer):**
   * **Обладнання:** L2-комутатори (Access Switches SW-1, SW-2, SW-3) та Точки доступу (Wi-Fi AP).
   * **Функції:** Підключення ПК, принтерів, IP-телефонів; прив'язка портів до відповідних VLAN (802.1Q tagging), безпека портів (Port Security, DHCP Snooping).

### 1.4. Схема логічної топології мережі

```
                      [ Інтернет / Зовнішня мережа ]
                        /                        \
           (Порт WAN1 / IP_ISP1)          (Порт WAN2 / IP_ISP2)
                      /                            \
        +------------------------------------------------+
        |  РІВЕНЬ ЯДРА (Core Layer): Firewall / Router  |
        +------------------------------------------------+
             | (Port 80/443 DMZ)               | (Trunk 802.1Q)
             v                                 v
   +--------------------+           +-------------------------------+
   | VLAN 40: DMZ / Web |           | РІВЕНЬ РОЗПОДІЛУ (Distr.):    |
   | 192.168.100.112/29 |           | L3 Switch (Inter-VLAN Router) |
   | Web-Server (P:443) |           +-------------------------------+
   +--------------------+               /          |          \
                                       /           |           \ (Trunk)
                                      /            |            \
                                (Trunk)         (Trunk)          v
                                  /                |    +------------------+
                                 v                 v    |  Access SW-3     |
                      +------------------+ +-----------+|  (VLAN 30: Fin)  |
                      |  Access SW-1     | | Access SW2|+------------------+
                      |  (VLAN 10: IT)   | | (VLAN 20) |         |
                      +------------------+ +-----------+         v
                               |                 |       [ ПК Бухгалтера ]
                               v                 v       192.168.100.98:8080
                        [ ПК Розробника ]   [ ПК Менеджера ]
                        192.168.100.10      192.168.100.66
```

### 1.5. Резервування та відмовостійкість каналу зв'язку

Для забезпечення відмовостійкості на рівнях 1–3 реалізовано:
1. **Dual WAN (Multi-homing):** Маршрутизатор ядра підключений до ISP1 (основний) та ISP2 (резервний).
2. **Моніторинг стану (Link Health Check / IP SLA):** Маршрутизатор регулярно відправляє ICMP-запити (ping) на зовнішні IP-адреси. У разі виявлення втрати пакетів на каналі ISP1, таблиця маршрутизації автоматично змінює default gateway на ISP2 ($0.0.0.0/0 \rightarrow \text{Gateway\_ISP2}$).
3. **L2 Redundancy (STP):** У разі використання дубльованих зв'язків між комутаторами розгортається протокол Spanning Tree Protocol (RSTP, 802.1w) для запобігання мережевим петлям.

## Завдання 2: Порівняльний аналіз режимів мереж контейнерів

| Критерій порівняння | Режим `Bridge` | Режим `Host` | Режим `Overlay` |
| ----- | ----- | ----- | ----- |
| **Рівень ізоляції** | **Високий.** Контейнер отримує власну віртуальну мережеву адресу в ізольованому мосту на хості. | **Відсутній.** Контейнер використовує мережевий стек хоста напряму без віртуалізації. | **Високий.** Ізольована логічна тунельована мережа поверх фізичної інфраструктури. |
| **Продуктивність / Швидкість** | Середня (наявні витрати ресурсів на NAT та проксування портів через `iptables`). | **Максимальна** (пряма робота з мережевим інтерфейсом хоста без накладних витрат). | Нижча за Bridge/Host через накладні витрати на инкапсуляцію/декапсуляцію (VXLAN). |
| **Підтримка Service Discovery (DNS)** | **Повна.** Вбудований Docker DNS резолвить імена контейнерів усередині Compose-мережі. | **Відсутня.** Сервіси повинні звертатися через `localhost` або фіксовані порти хоста. | **Повна.** Працює між різними фізичними вузлами кластера (наприклад, у Kubernetes / Docker Swarm). |
| **Масштабованість** | Обмежена одним фізичним хостом. | Обмежена одним хостом; можливі конфлікти портів. | **Мультихостова.** Об'єднує контейнери на багатьох фізичних серверах. |
| **Типовий випадок використання** | Стандартне локальне розгортання мультиконтейнерних застосунків (Frontend + API + DB). | Високонавантажені сервіси (Streaming, VoIP), де критична кожна мікросекунда затримки. | Розподілені кластерні системи, мікросервісні архітектури в хмарах та Kubernetes. |

## Відповіді на контрольні запитання

### 1. Які етапи включає проєктування мережі?
Проєктування мережі — це послідовний процес, що складається з 5 основних етапів:
1. **Збір вимог (Requirements):** Визначення кількості користувачів, обсягів трафіку, типів застосунків, вимог до швидкодії, надійності та безпеки.
2. **Логічне проєктування (Logical Design):** Визначення топології, сегментація на підмережі/VLAN, розробка правил фільтрації трафіку та підписання портів взаємодії.
3. **Фізичне проєктування (Physical Design):** Вибір конкретного обладнання, розрахунок трасування кабелів, розміщення серверних шаф та розеток.
4. **Адресний план (Addressing Plan):** Розподіл IP-адрес методом VLSM, розробка схем static/DHCP адресації із запасом на зростання.
5. **Документування (Documentation):** Створення схем топології, таблиць комутації, специфікацій обладнання та регламентів обслуговування.

### 2. Опишіть призначення кожного з трьох рівнів ієрархічної моделі.
* **Рівень доступу (Access Layer):** Підключає кінцеві пристрої (ПК, IP-телефони, точки доступу). Забезпечує первинну безпеку (Port Security), маркування VLAN та фільтрацію на L2.
* **Рівень розподілу (Distribution Layer):** Агрегує трафік від комутаторів доступу, виконує маршрутизацію між VLAN, застосовує політики безпеки (ACL), QoS та здійснює термінація broadcast-доменів.
* **Рівень ядра (Core Layer):** Забезпечує максимально швидку транзитну передачу трафіку між вузлами розподілу та зовнішніми мережами. Оптимізований виключно під швидкість і надійність, без складної обробки пакетів.

### 3. Чим bridge-режим контейнерної мережі відрізняється від host-режиму?
У режимі **bridge** контейнер працює у власному ізольованому мережевому просторі (network namespace) із власною IP-адресою та віртуальним мережевим інтерфейсом, а доступ ззовні здійснюється через NAT/Port Mapping. У режимі **host** контейнер позбавлений мережевої ізоляції — він розділяє IP-адресу та портовий простір безпосередньо з хост-машиною.

### 4. Що таке VPC і з яких елементів вона складається?
**VPC (Virtual Private Cloud)** — це ізольований віртуальний сегмент хмарної мережі, виділений конкретному користувачеві для розгортання ресурсів у безпечному середовищі.
**Основні елементи VPC:**
* *Підмережі (Subnets):* Публічні (мають вихід в інтернет) та приватні (ізольовані).
* *Таблиці маршрутизації (Route Tables):* Правила спрямування трафіку між підмережами й шлюзами.
* *Інтернет-шлюзи (Internet Gateways) / NAT Gateways:* Для забезпечення доступу до зовнішніх мереж.
* *Групи безпеки (Security Groups) та мережеві ACL (NACL):* Віртуальні фаєрволи для ресурсу чи підмережі.

### 5. Яку інформацію дають SNMP і NetFlow при моніторингу мережі?
* **SNMP (Simple Network Management Protocol):** Дає інформацію про **стан пристрою** в конкретні моменти часу (стан інтерфейсів up/down, завантаження CPU та RAM, температура, лічильники помилок CRC, Uptime).
* **NetFlow:** Дає інформацію про **потоки трафіку** (хто, з ким, за яким протоколом, на який порт та в якому обсязі передає дані). Використовується для аналізу споживання смуги пропускання та виявлення аномалій.

### 6. Чому актуальна документація мережі скорочує час усунення інциденту?
Актуальна документація прискорює усунення несправностей (MTTR — Mean Time to Repair), оскільки інженеру не потрібно витрачати час на ручну розвідку топології ("куди веде цей кабель", "який IP у бази даних"). Вона дає змогу одразу локалізувати місце збою, зіставити симптоми з відповідним сегментом та застосувати регламент відновлення.

### 7. Чому в bridge-режимі сервіси можуть звертатись один до одного за іменем, а в host-режимі — ні?
У режимі **bridge** Docker/Orchestrator запускає вбудований DNS-сервер, який автоматично відстежує створення контейнерів і співвідносить їхні імена сервісів із поточними внутрішніми IP-адресами. У режимі **host** вбудований DNS-сервер контейнерної платформи не використовується, оскільки контейнери не мають власних унікальних IP-адрес у віртуальній мережі, а виступають як звичайні процеси хоста.

### 8. Чому правило групи безпеки "дозволити вхід з 0.0.0.0/0" вважається порушенням принципу найменших привілеїв для внутрішнього сервісу?
Маска `0.0.0.0/0` відкриває доступ до сервісу абсолютно для будь-якого хоста у глобальній мережі Інтернет. Якщо це внутрішній сервіс (база даних, API), йому категорично не потрібні прямі з'єднання ззовні. Відкриття порту створює критичну вразливість: у разі відсутності чи прорахунку в автентифікації зловмисник з інтернету отримує прямий доступ до даних, минаючи захисний фронтенд.

### 9. У якому порядку і чому саме в такій послідовності варто перевіряти причину недоступності сервісу?
Діагностика здійснюється від найпростіших і найшвидших перевірок до найскладніших:
1. **Перевірка DNS та доступності порту (`nslookup`, `nc -zv`, `telnet`):** Швидко визначає, чи існує маршрут на транспортному/мережевому рівні і чи слухає сервіс порт.
2. **Перевірка стану служби (Health Check / HTTP response):** Якщо порт відкритий, перевіряється, чи відповідає сам застосунок (наприклад, код `200 OK` на `/health`), чи він впав у помилку `500/503`.
3. **Аналіз логів та глибших рівнів (Logs, CPU/RAM, Routing, Physical):** Виконується лише тоді, коли мережа і порт працюють, але сервіс працює некоректно чи зависає під навантаженням.
