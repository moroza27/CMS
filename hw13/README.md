# Домашня робота з лекції № 13

## 1. Порівняння топологій мережі

Для зірки вважаю, що всі вузли підключені окремими кабелями до центрального комутатора. Для кільця припускаю просте односпрямоване кільце без резервного шляху.

| Ознака | Зірка | Кільце |
|---|---|---|
| Кількість кабельних сегментів для `N` вузлів | `N` кабелів від вузлів до центрального пристрою | `N` сегментів, що з'єднують вузли в замкнене кільце |
| Відмова одного вузла | Зазвичай від'єднується лише цей вузол; інші продовжують працювати | У простому кільці може порушитися зв'язок між усіма вузлами |
| Відмова центрального пристрою / одного сегмента | Відмова центрального пристрою зупиняє обмін між вузлами | Обрив одного сегмента розриває кільце та може зупинити обмін у всій мережі |

## 2. Перевірка з'єднання в браузері

Для прикладу перевірив адресу `https://example.com/`: контрольний запит `curl` використав HTTPS на типовому порту **443** і протокол **HTTP/1.1**. У браузері це можна перевірити через F12 → Network → оновити сторінку → вибрати запит. Версія протоколу зазвичай показана у стовпці `Protocol`, а порт — у `Remote Address` (або його можна визначити за схемою URL: для HTTPS типовий порт 443, для HTTP — 80); ці значення не обов'язково відображаються в `Request Headers`. У різних браузерах, мережах і запусках узгоджений протокол може відрізнятися.

## 3. Комутація каналів і комутація пакетів

За комутації каналів на весь сеанс заздалегідь встановлюється окремий шлях і резервується його ресурс, навіть коли дані тимчасово не передаються. За комутації пакетів повідомлення ділиться на пакети, які передаються спільними каналами й можуть проходити різними маршрутами. Тому пакетна комутація ефективніше використовує мережу для нерівномірного трафіку, але час доставки пакетів може змінюватися.
