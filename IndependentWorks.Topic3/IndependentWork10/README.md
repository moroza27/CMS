# Звіт з самостійної роботи №10

**Варіант:** №10

### Завдання 1. Основні відомості про RFC

Для протоколу **POP3** знайшла специфікацію у реєстрі IETF Datatracker:

| Поле | Значення з титульної сторінки RFC |
| ----- | ----- |
| **Номер RFC** | RFC 1939 |
| **Повна назва** | Post Office Protocol - Version 3 |
| **Рік публікації** | Травень 1996 року |
| **Статус** | Internet Standard (STD 53) |
| **Автор / Організація** | J. Myers (Carnegie Mellon), M. Rose (Dover Beach Consulting) |

* **Пряме посилання на першоджерело:** <https://datatracker.ietf.org/doc/rfc1939/>

### Завдання 2. Перевірка чинності документа

Документ **RFC 1939** є **чинним** (статус *Internet Standard / STD 53*). Згідно з даними реєстру Datatracker:
* Він замінив застарілу специфікацію **RFC 1725** (поля `Obsoletes: 1725`).
* Він **не замінений** новішим документом (поле `Obsoleted by` відсутнє), проте був частково доповнений пізнішими специфікаціями в полі `Updated by` (зокрема RFC 2449, RFC 6186, RFC 8314).

### Завдання 3. Конкретні факти зі специфікації RFC

1. **Розділ 3 (Basic Operation — Стани сесії та порт):**
   Сервер POP3 за замовчуванням слухає запити на **TCP-порту 110**. Взаємодія між клієнтом і сервером проходить через три чітко визначені стани: `AUTHORIZATION` (авторизація користувача), `TRANSACTION` (перегляд та маркування повідомлень на видалення) та `UPDATE` (остаточне видалення листів і завершення сесії після команди `QUIT`).

2. **Розділ 3 & Розділ 5 (Response Formats — Маркери відповідей та завершення):**
   Усі відповіді POP3-сервера обов'язково починаються з одного з двох статусних індикаторів: `+OK` (позитивна відповідь) або `-ERR` (помилка). Для команд, які повертають декілька рядків даних (наприклад, `LIST` або `RETR`), кінцем передачі вважається окремий рядок, який містить лише одну крапку, після якої йдуть символи `CRLF` (`.\r\n`).

### Завдання 4. Підгрупи родини IEEE 802

| Підгрупа | Область відповідальності |
| ----- | ----- |
| **IEEE 802.1** | Відповідає за загальну архітектуру локальних мереж, мости, віртуальні мережі (VLAN 802.1Q) та керування мережевою інфраструктурою. |
| **IEEE 802.3** | Визначає фізичний та канальний (MAC) рівні для дротових мереж Ethernet через кручену пару та оптичне волокно. |
| **IEEE 802.11** | Визначає специфікації фізичного рівня та керування доступом до середовища (MAC) для бездротових локальних мереж (Wi-Fi). |

### Відповіді на контрольні запитання

1. **Чим статус «Proposed Standard» відрізняється від «Internet Standard»?**
   *Proposed Standard* — це специфікація, яка пройшла перевірку IESG, вважається стабільною та готовою до впровадження, але ще перебуває на етапі накопичення практичного досвіду. *Internet Standard* (найвищий рівень) надається документам, які мають значний успішний досвід використання у реальних мережах та доведену сумісність множини незалежних реалізацій.

2. **Що означають поля «Obsoletes» і «Updated by» на сторінці RFC?**
   * `Obsoletes` вказує номери старих RFC, які даний документ повністю замінює чи скасовує.
   * `Updated by` вказує номери новіших RFC, які доповнюють, уточнюють або змінюють окремі частини даного документа без його повного скасування.

3. **За що відповідає підгрупа IEEE 802.1 і чим вона відрізняється від 802.3?**
   IEEE 802.1 займається міжмережевою взаємодією вищого рівня в межах L2 (маршрутизація кадрів, мости, VLAN, безпека портів 802.1X), тоді як IEEE 802.3 спеціалізується безпосередньо на технічній реалізації дротового фізичного середовища та форматі кадру Ethernet.

4. **Чому недостатньо знайти будь-який RFC з назвою протоколу в заголовку, не перевіривши актуальність?**
   Мережеві протоколи постійно еволюціонують, у них виправляють уразливості безпеки та оптимізують заголовок. Якщо взяти застарілий RFC (наприклад, RFC 1081 для POP3), вивчені факти або команди можуть виявитися застарілими чи відсутніми у сучасних реалізаціях.
