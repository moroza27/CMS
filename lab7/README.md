## 3. Хід виконання роботи та конфігураційні команди

### Етап 1. Створення базової топології та початкове тестування
1. У Cisco Packet Tracer розміщено 1 комутатор (Cisco 2960), 1 маршрутизатор (Cisco 1941 або 2911) та 4 ПК.
2. ПК з'єднані з комутатором прямим мідним кабелем (Copper Straight-Through).
3. Спочатку всі порти належать стандартному VLAN 1. Експеримент показує, що якщо призначити всім ПК IP з однієї підмережі (наприклад `192.168.1.0/24`), ping проходить між усіма ПК без обмежень.

### Етап 2. Налаштування VLAN та перевірка ізоляції L2

На комутаторі `Switch0` створено VLAN 16 та 26 і прив'язано порти доступу:

```text
Switch> enable
Switch# configure terminal
Switch(config)# vlan 16
Switch(config-vlan)# name LEGAL
Switch(config-vlan)# vlan 26
Switch(config-vlan)# name SUPPORT
Switch(config-vlan)# exit

! Призначення портів для VLAN 16
Switch(config)# interface range fastEthernet 0/1 - 10
Switch(config-if-range)# switchport mode access
Switch(config-if-range)# switchport access vlan 16
Switch(config-if-range)# exit

! Призначення портів для VLAN 26
Switch(config)# interface range fastEthernet 0/11 - 20
Switch(config-if-range)# switchport mode access
Switch(config-if-range)# switchport access vlan 26
Switch(config-if-range)# exit
```

#### Результати тестування перевірки ping (Етап 2):
* **Ping у межах VLAN 16 (від PC1 до PC2):** `SUCCESSFUL` (затримка $< 1\text{ мс}$).
* **Ping у межах VLAN 26 (від PC3 до PC4):** `SUCCESSFUL` (затримка $< 1\text{ мс}$).
* **Ping між VLAN (від PC1 до PC3):** `FAILED` (Destination Host Unreachable).

> **Пояснення:** Комутатор розділив фізичний пристрій на два незалежні широкомовні домени. Кадри з VLAN 16 фізично не передаються на порти VLAN 26, тому на рівні L2 доступ перекрито.

### Етап 3. Налаштування міжмережевої маршрутизації (Router-on-a-Stick)

Для забезпечення зв'язку між VLAN 16 та VLAN 26 додано маршрутизатор та налаштовано транковий порт на комутаторі та субінтерфейси на маршрутизаторі.

#### 1. Конфігурація транкового порту на комутаторі (`Switch0`):
```text
Switch(config)# interface gigabitEthernet 0/1
Switch(config-if)# switchport mode trunk
Switch(config-if)# exit
```

#### 2. Конфігурація субінтерфейсів на маршрутизаторі (`Router0`):
```text
Router> enable
Router# configure terminal
Router(config)# interface gigabitEthernet 0/0
Router(config-if)# no shutdown
Router(config-if)# exit

! Субінтерфейс для VLAN 16
Router(config)# interface gigabitEthernet 0/0.16
Router(config-subif)# encapsulation dot1Q 16
Router(config-subif)# ip address 10.10.16.1 255.255.255.0
Router(config-subif)# exit

! Субінтерфейс для VLAN 26
Router(config)# interface gigabitEthernet 0/0.26
Router(config-subif)# encapsulation dot1Q 26
Router(config-subif)# ip address 10.10.26.1 255.255.255.0
Router(config-subif)# exit
```

## Відповіді на контрольні запитання

1. **Як комутатор наповнює таблицю MAC-адрес і що робить з кадром невідомого призначення?**  
   *Відповідь:* Комутатор аналізує **MAC-адресу джерела (Source MAC)** у заголовку вхідного кадру та асоціює її з портом, на який надійшов кадр. Якщо адреса призначення є невідомою (відсутня в таблиці) або широкомовною (`FF:FF:FF:FF:FF:FF`), комутатор лавиноподібно розсилає кадр на всі порти поточного VLAN, крім вхідного (Unboxing/Flooding).

2. **Чому широкомовний кадр однієї VLAN не потрапляє в іншу VLAN на тому самому комутаторі?**  
   *Відповідь:* Оскільки VLAN логічно розділяє комутатор на незалежні широкомовні домени (Broadcast Domains). Таблиця комутації ізолює розсилку кадрів у межах конкретного тегу VLAN ID, запобігаючи виходу широкомовних пакетів за межі свого сегмента.

3. **Чим порт доступу (access) відрізняється від транкового (trunk) за призначенням і форматом кадру?**  
   *Відповідь:* Порт **Access** передає трафік лише однієї конкретної VLAN для кінцевого пристрою і передає кадри **без тегів** (Untagged). Порт **Trunk** з'єднує мережеві пристрої (комутатор-комутатор або комутатор-маршрутизатор), передає трафік багатьох VLAN та додає 4-байтовий тег **IEEE 802.1Q** до кожного кадру.

4. **Що таке тег IEEE 802.1Q і навіщо він потрібен на транку?**  
   *Відповідь:* Це стандартний заголовок розміром 4 байти, який вставляється у заголовок Ethernet-кадру. Він містить поле **VLAN ID** (12 біт), яке вказує, до якої саме VLAN належить дане повідомлення при проходженні через спільний транковий канал.

5. **Порівняйте Router-on-a-Stick і SVI як способи міжVLAN маршрутизації.**  
   *Відповідь:* **Router-on-a-Stick** використовує окремий маршрутизатор L3, підключений до L2-комутатора одним транковим каналом із розділенням на віртуальні субінтерфейси. **SVI (Switch Virtual Interface)** реалізується безпосередньо усередині L3-комутатора (Multi-Layer Switch) за допомогою віртуальних інтерфейсів VLAN, що забезпечує значно вищу швидкість (комутація на апаратному рівні ASIC).

6. **Чому до налаштування маршрутизації вузли різних VLAN не обмінювалися пакетами, хоча були підключені до одного комутатора?**  
   *Відповідь:* Оскільки комутатор L2 працює виключно на канальному рівні (L2 OSI) і не вміє модифікувати теги або перенаправляти кадри між різними широкомовними доменами. Для зв'язку між різними підмережами необхідний пристрій мережевого рівня (L3), який аналізує IP-адреси.

## Домашнє завдання

1. **Аналіз розсилки кадру в режимі симуляції:**  
   Широкомовний кадр (`FF:FF:FF:FF:FF:FF`) розсилається на всі порти в межах одного VLAN, оскільки в таблиці MAC-адрес відсутній конкретний порт для цієї адреси, і правило Flooding зобов'язує доставити його всім учасникам домену. Звичайний одноадресний кадр (Unicast) надсилається точково на один конкретний порт, бо в таблиці MAC-адрес комутатора вже існує чітка відповідність: `MAC-адреса призначення -> Порт`.

2. **Ізоляція ARP та необхідність L3-маршрутизації:**  
   Запит ARP є широкомовним кадровим повідомленням (L2 broadcast). При наявності двох VLAN комутатор блокує поширення ARP-запиту з VLAN 16 у VLAN 26. Щоб трафік міг переходити між ними, до топології необхідно додати маршрутизатор (або L3-комутатор), налаштувати шлюзи за замовчуванням та підключити транковий канал з інкапсуляцією IEEE 802.1Q.
