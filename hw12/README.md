# Домашня робота з лекції № 12

## 1. Закон Амдала

Послідовна частина програми становить `f = 0,25`, а кількість процесорів позначимо `p`. За законом Амдала:

```text
S = 1 / (f + (1 - f) / p)
```

Для 4 процесорів:

```text
S₄ = 1 / (0,25 + 0,75 / 4)
   = 1 / 0,4375
   ≈ 2,29
```

Для 8 процесорів:

```text
S₈ = 1 / (0,25 + 0,75 / 8)
   = 1 / 0,34375
   ≈ 2,91
```

Для 16 процесорів:

```text
S₁₆ = 1 / (0,25 + 0,75 / 16)
    = 1 / 0,296875
    ≈ 3,37
```

Зі збільшенням кількості процесорів прискорення зростає, але приріст стає меншим. Навіть за нескінченної кількості процесорів прискорення не перевищить `1 / 0,25 = 4`, бо чверть програми залишається послідовною. Тому подальше додавання ядер для цієї програми має дедалі менший сенс; варто враховувати вартість ядер і можливість зменшити послідовну частину.

## 2. Конфлікт конвеєра за даними

```text
ADD R1, R2, R3   ; R1 = R2 + R3
SUB R4, R1, R5   ; R4 = R1 - R5
```

Тут виникає **конфлікт за даними** — залежність типу RAW (Read After Write). Інструкція `ADD` записує результат у `R1`, а наступна інструкція `SUB` читає `R1`. У конвеєрі Fetch–Decode–Execute–Memory–Write друга інструкція може дійти до читання операндів раніше, ніж перша завершить запис результату на стадії Write. Тоді `SUB` може отримати старе значення `R1`. Процесор розв'язує таку ситуацію, наприклад, пересиланням результату між стадіями або затримкою конвеєра (stall), доки правильне значення не стане доступним.

## 3. Приклад конфлікту за керуванням

```text
    ADD  R1, R1, #1       ; збільшити лічильник
    CMP  R1, #10          ; порівняти лічильник з 10
    BLT  loop             ; якщо R1 < 10, перейти на loop
    MOV  R2, #0            ; інструкція після циклу
```

Інструкція `BLT` змінює адресу наступної інструкції залежно від результату порівняння. Поки умова переходу не визначена, процесор може не знати, звідки вибирати наступну інструкцію: з адреси `loop` чи з інструкції після переходу. Якщо конвеєр завантажив інструкції з неправильного шляху, їх доведеться відкинути; також можливе призупинення вибірки до визначення результату. Це і є **конфлікт за керуванням** (control hazard).
