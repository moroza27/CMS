## 1. Подання числа −19 у 8-бітному додатковому коді

Спочатку запишемо модуль числа 19 у двійковій системі: $19_{10}=10011_2$. Для 8-бітного прямого коду відводимо один старший біт на знак і сім бітів на модуль:

```text
Прямий код −19:       10010011
Обернений код:        11101100
Додаємо 1:            11101100
										+ 00000001
											--------
Додатковий код −19:   11101101
```

Отже, число $-19$ у 8-бітному додатковому коді — **11101101**.

## 2. Додавання чисел у додатковому коді

```text
	01111000   (120)
+ 00010101   (21)
----------
	10001101
```

Обидва доданки додатні: їхні знакові біти дорівнюють 0. У результаті знаковий біт дорівнює 1, тобто 8-бітний результат виглядає від’ємним. Це означає **переповнення**: сума $120+21=141$ більша за найбільше додатне число, яке можна подати в 8-бітному додатковому коді ($127$). У цих межах бітовий результат `10001101` інтерпретується як $-115$, а не як правильна сума $141$.

Ознака переповнення: **два числа одного знака дали результат іншого знака**. Переносу за межі старшого біта немає, але це не скасовує переповнення для знакових чисел.

## 3. Число 12.5 у форматі IEEE 754 single precision

Переведемо число у двійковий вигляд:

```text
12.5₁₀ = 1100.1₂ = 1.1001₂ × 2³
```

- **Знак:** `0`, оскільки число додатне.
- **Порядок у нормалізованому записі:** $3$, бо мантиса має вигляд $1.1001_2 \times 2^3$. Зміщений порядок дорівнює $3+127=130$, тобто `10000010`.
- **Мантиса:** `10010000000000000000000` (початкову одиницю після нормалізації не зберігають).
- **Повний 32-бітний запис:** `0 10000010 10010000000000000000000` (`01000001010010000000000000000000` у суцільному вигляді).

Якщо під «найближчим степенем двійки» мається на увазі найближче до самого числа значення, то це $2^4=16$ (воно ближче до $12.5$, ніж $2^3=8$). Це не суперечить порядку $3$ у нормалізованому записі IEEE 754: показник задає масштаб мантиси, а не найближчий степінь двійки.

Число $12.5$ подається точно, бо його двійковий запис скінченний: $1100.1_2$. Десяткове $0.1=1/10$ у двійковій системі має нескінченний періодичний дріб, тому у форматі з обмеженою кількістю бітів його доводиться округлювати.
